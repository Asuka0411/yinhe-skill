# 一键购买 Wishlist 与补货回运原子功能 PRD

日期：2026-06-08

## 背景

当前脚本已经有原子功能测试区，并且 `一键购买 wishlist` 按钮已经展示在 `一键卖货` 下方，但真实流程仍处于待接入状态。

用户希望把完整补货链拆成多个可单独点击、单独验证的原子功能按钮，按钮放在对应功能的配置面板内。每个原子功能都要能独立写日志、独立失败、独立停止，最终再组合成稳定的一键补货回运流程。

## 产品目标

构建一套“从当前基地生成补货 wishlist 到交易所购买、装船、补给飞船并发回基地”的按钮式原子流程。

第一阶段目标不是直接做黑盒一键全自动，而是先拆小、逐个验证：
- 每一步都能单独点击测试
- 每一步都有明确前置条件、成功条件、失败日志
- 每一步都可以被完整链路复用
- 完整链路只负责按顺序编排已验证的原子功能

## 面板要求

`一键购买 wishlist` 的配置面板内要展示“流程拆分后的原子功能测试按钮”。

展示规则：
- 主按钮仍为 `一键购买 wishlist`
- 主按钮右侧保留 `展开 / 收起`
- 展开后展示该功能的配置与原子步骤按钮
- 原子步骤按钮按真实执行顺序排列
- 每个按钮旁边展示状态标记：`待接入`、`可测试`、`已验证`
- 每个按钮执行时写入面板日志和运行历史
- 运行中允许点击全局 `停止`

## 完整业务流程

补货回运完整流程如下：

1. 选中当前基地
2. 清空当前基地绑定的 wishlist
3. 判断当前基地对应飞船是否在交易所
4. 创建适当天数的补给 wishlist
5. 去交易所页面
6. 找到创建的 wishlist
7. 按 wishlist 逐项购买
8. 把购买物资全部转移到飞船
9. 给飞船补油
10. 修理飞船
11. 发船回基地

## 原子功能拆分

### 1. 读取当前基地

按钮名：`读取当前基地`

目的：
- 明确当前脚本操作的是哪个基地
- 初始化基地级配置、默认 wishlist、目标飞船匹配规则

前置条件：
- 用户当前在游戏登录态页面
- 页面能读取到当前基地或基地上下文

成功条件：
- 读取到 `base.id`
- 读取到 `base.name`
- 读取到 `base.planetId` 或可解析的 wishlist 归属 ID
- 配置面板显示当前基地信息

失败条件：
- 当前页面不是基地相关页面
- Local API 读取失败
- 无法从 URL 或页面推断基地

输出：
- `base`
- `baseConfig`
- `wishlistId`

### 2. 清空当前基地 wishlist

按钮名：`清空基地 wishlist`

目的：
- 删除当前基地绑定 wishlist 中上一轮残留物资
- 保证后续生成的是本轮补货需求，不混入旧数据

前置条件：
- 已读取当前基地
- 已解析当前基地对应的 `wishlistId`

成功条件：
- 目标 wishlist 条目数量变为 0
- 日志记录清空前数量与清空后数量

失败条件：
- 找不到目标 wishlist
- 找不到清空按钮或接口
- 清空后仍存在残留条目

输出：
- `wishlistId`
- `clearedCount`

### 3. 检查飞船在交易所

按钮名：`检查飞船在交易所`

目的：
- 判断当前基地对应飞船是否可执行补货回运
- 防止飞船不在交易所时误买、误装、误发船

前置条件：
- 已读取当前基地
- 可读取公司飞船列表或页面飞船列表

成功条件：
- 找到当前基地对应飞船
- 飞船位置为交易所
- 飞船不是运输中

失败条件：
- 未找到对应飞船
- 飞船在基地
- 飞船运输中
- 飞船状态不可操作

输出：
- `ship`
- `shipLocation`
- `exchangeWarehouseId`

### 4. 创建适当天数补给 wishlist

按钮名：`创建补给 wishlist`

目的：
- 复用游戏 `Resupply` 页面计算缺料
- 按配置的补齐天数生成当前基地 wishlist
- 在重量或资金超限时缩减天数重新生成

前置条件：
- 已读取当前基地
- 已清空当前基地 wishlist
- 已读取补齐天数配置
- 最好已确认飞船在交易所，用于载重约束

成功条件：
- 进入当前基地 `Resupply` 页面
- 设置目标补齐天数
- 勾选全部需要补给的物资
- 点击游戏的 `Add to Wishlist`
- 读取到生成后的 wishlist 条目
- wishlist 总重量不超过飞船可用载重
- wishlist 估算总价不超过可用资金

失败条件：
- 无法进入 `Resupply`
- 无法设置天数
- 无法勾选条目
- 无法添加到 wishlist
- 缩减到最低天数仍超重或资金不足

输出：
- `wishlistRows`
- `finalDays`
- `estimatedWeight`
- `estimatedCost`

### 5. 切换到交易所页面

按钮名：`打开交易所`

目的：
- 进入购买与装船操作所在页面

前置条件：
- 已读取当前基地

成功条件：
- 当前页面切换到交易所
- 能看到交易所搜索、购买或仓库区域

失败条件：
- 导航失败
- 页面加载超时
- 交易所关键控件缺失

输出：
- `exchangePageReady`

### 6. 读取并确认 wishlist

按钮名：`读取 wishlist`

目的：
- 在购买前再次读取当前基地绑定 wishlist
- 展示将要购买的物资列表，避免买错上一轮残留

前置条件：
- 已创建补给 wishlist
- 已打开交易所页面

成功条件：
- 读取到与当前基地匹配的 wishlist
- 物资名称、数量、估算价格可展示

失败条件：
- wishlist 为空
- wishlist 归属不匹配
- 物资 ID 无法映射名称

输出：
- `wishlistRows`

### 7. 购买 wishlist

按钮名：`购买 wishlist`

目的：
- 在交易所按 wishlist 逐项购买补给物资

前置条件：
- 已打开交易所页面
- 已读取 wishlist
- 可用资金足够

成功条件：
- 对每个 wishlist 条目执行：搜索物资、点击物资行、填写数量、点击最终 `Buy`
- 日志记录每个物资购买结果

失败条件：
- 找不到物资行
- 找不到数量输入框
- 找不到最终 `Buy` 按钮
- 某项购买失败
- 用户点击停止

输出：
- `buySummary`
- `failedItems`

处理规则：
- 第一版遇到任一购买失败就停止后续购买，避免半自动状态下继续误操作
- 已买项目必须写入摘要

### 8. 全部转移到飞船

按钮名：`转移到飞船`

目的：
- 把本轮购买的补给物资从交易所仓库转移到当前飞船

前置条件：
- 飞船在交易所
- 本轮有购买结果或可读取交易所仓库库存
- 交易所页面可打开仓库 / 飞船转移界面

成功条件：
- 本轮 wishlist 中每种物资已转移到目标飞船
- 日志记录每项转移数量

失败条件：
- 找不到目标飞船
- 找不到转移入口
- 找不到数量输入框
- 飞船载重不足
- 某项库存不足

输出：
- `transferSummary`

### 9. 飞船补油

按钮名：`飞船补油`

目的：
- 确保飞船有足够 `Antimatter` 执行返航

前置条件：
- 飞船在交易所
- 交易所仓库或飞船上有 `Antimatter`
- 可打开飞船补油界面

成功条件：
- 飞船燃料达到目标值或游戏允许的满油状态

失败条件：
- 缺少 `Antimatter`
- 找不到补油入口
- 补油按钮不可用

输出：
- `fuelSummary`

### 10. 修理飞船

按钮名：`修理飞船`

目的：
- 使用 `Ship Repair Kit` 修理飞船，降低返航失败风险

前置条件：
- 飞船在交易所
- 交易所仓库或飞船上有 `Ship Repair Kit`
- 可打开飞船修理界面

成功条件：
- 飞船耐久达到目标值或游戏允许的满修状态

失败条件：
- 缺少 `Ship Repair Kit`
- 找不到修理入口
- 修理按钮不可用

输出：
- `repairSummary`

### 11. 发船回基地

按钮名：`发船回基地`

目的：
- 将飞船从交易所发回当前基地

前置条件：
- 飞船在交易所
- 已完成购买与装船
- 已补油
- 已修理或确认无需修理

成功条件：
- 选择目标为当前基地
- 动力模式选择普通
- 根据需要开启自动卸货
- 点击出发
- 飞船状态变为运输中

失败条件：
- 找不到目的地输入
- 找不到当前基地目的地
- 找不到动力模式
- 找不到自动卸货开关
- 找不到出发按钮
- 点击后状态未变化

输出：
- `flightSummary`
- `waitMs`

## 编排功能

### 一键购买 wishlist

第一阶段定义：
- 只执行 `读取当前基地`、`读取 wishlist`、`打开交易所`、`购买 wishlist`
- 不清空 wishlist
- 不创建 wishlist
- 不装船
- 不发船

用途：
- 单独验证“已有 wishlist 的购买能力”
- 降低真实交易风险

### 一键补货回运

第二阶段定义：
- 按完整流程执行所有原子功能
- 任何关键步骤失败立即停止
- 进入运输中后以 `waiting` 结束

用途：
- 替代旧 `补货` 链路，成为稳定的补货主流程

## 配置项

当前阶段需要新增或确认以下配置：

- `补齐天数`：已有配置，创建 wishlist 时使用
- `最低补齐天数`：缩减天数的下限，默认 1
- `自动卸货`：发船回基地时默认开启
- `补油目标`：默认尽量补满
- `修理目标`：默认尽量修满
- `购买前预览`：默认关闭；后续可选开启确认模式
- `失败后继续`：第一版默认关闭

配置保存规则：
- 每一项新增配置都必须同步保存、读取、渲染
- 不得因为保存其它配置而丢失已有物资图标、白名单、黑名单字段

## 状态与日志

每个原子功能都要写入统一步骤日志：
- 开始时间
- 前置条件检查结果
- 关键点击动作
- 成功摘要
- 失败原因
- 已停止状态

日志文字必须能让用户判断当前卡在哪一步，不能只写“失败”。

## 风险控制

真实购买与发船有经济和时间成本，必须按下列规则控制：

- 没有明确 wishlist 时不购买
- 资金不足时不购买
- 飞船不在交易所时不装船、不补油、不修理、不发船
- 目标基地不明确时不发船
- 任一关键 UI 控件找不到时停止
- 默认不使用热注入作为正式发布方式
- 每次脚本更新后执行 `npm run release:local`

## 验收标准

第一阶段验收：
- `一键购买 wishlist` 展开面板内能看到所有拆分按钮
- 每个按钮点击后都有日志，即使尚未接入真实流程也能显示明确状态

第一版购买验收：
- 已有 wishlist 时可以单独执行购买
- 空 wishlist 不购买
- 资金不足不购买
- 任一购买失败时停止后续购买

完整补货回运验收：
- 当前基地明确
- 当前基地 wishlist 能清空并重建
- 飞船必须在交易所
- wishlist 能按适当天数生成
- 购买物资能转移到飞船
- 飞船能补油、修理
- 飞船能以普通动力发回当前基地并开启自动卸货
- 面板日志能还原完整执行过程
