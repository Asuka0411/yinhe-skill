# 一键购买 Wishlist 与补货回运原子功能 PRD

日期：2026-06-08

## 背景

当前脚本已经有原子功能测试区，并且 `一键购买 wishlist` 按钮已经展示在 `一键卖货` 下方。补货回运流程已拆成可单独点击、单独验证的原子按钮，当前重点是继续按玩家实测结果推进后续步骤状态。

用户希望把完整补货链拆成多个可单独点击、单独验证的原子功能按钮，按钮放在对应功能的配置面板内。每个原子功能都要能独立写日志、独立失败、独立停止，最终再组合成稳定的一键补货回运流程。

## 当前实现状态

- 已完成 `读取当前基地`、`清空基地 wishlist`、`检查飞船在交易所`、`创建补给 wishlist`、`购买 wishlist`、`转移到飞船`、`飞船补油修理`、`一键补修理包、油`、`发船回基地`
- 已完成 `一键购买 wishlist` 与 `一键补货回运` 的主流程编排
- 已完成本地 harness 场景验证

当前仍需继续校准的点是：

- 06 之后步骤的真实登录态 Chrome 小额实机验证尚未补齐

## 产品目标

构建一套“从当前基地生成补货 wishlist 到交易所购买、装船、补给飞船并发回基地”的按钮式原子流程。

第一阶段目标不是直接做黑盒一键全自动，而是先拆小、逐个验证：
- 每一步都能单独点击测试
- 每一步都有明确前置条件、成功条件、失败日志
- 每一步都可以被完整链路复用
- 完整链路只负责按顺序编排已验证的原子功能

## 面板要求

`一键购买 wishlist` 的配置面板内要展示“流程拆分后的原子功能测试按钮”。

展示规则：
- 主按钮仍为 `一键购买 wishlist`
- 主按钮右侧保留 `展开 / 收起`
- 展开后展示该功能的配置与原子步骤按钮
- 原子步骤按钮按真实执行顺序排列
- 每个按钮旁边展示状态标记：`待接入`、`可测试`、`已验证`
- 每个按钮执行时写入面板日志和运行历史
- 运行中允许点击全局 `停止`

## 完整业务流程

补货回运完整流程如下：

1. 选中当前基地
2. 清空当前基地绑定的 wishlist
3. 判断当前基地对应飞船是否在交易所
4. 创建适当天数的补给 wishlist
5. 按 wishlist 逐项购买
6. 把购买物资按黑名单过滤后转移到飞船
7. 给所有在交易所的飞船补油并修理
8. 补齐交易所库存中的修理包和油
9. 发船回基地

## 原子功能拆分

### 1. 读取当前基地

按钮名：`读取当前基地`

目的：
- 明确当前脚本操作的是哪个基地
- 初始化基地级配置、默认 wishlist、目标飞船匹配规则

前置条件：
- 用户当前在游戏登录态页面
- 页面能读取到当前基地或基地上下文

成功条件：
- 读取到 `base.id`
- 读取到 `base.name`
- 读取到 `base.planetId` 或可解析的 wishlist 归属 ID
- 配置面板显示当前基地信息

失败条件：
- 当前页面不是基地相关页面
- Local API 读取失败
- 无法从 URL 或页面推断基地

输出：
- `base`
- `baseConfig`
- `wishlistId`

### 2. 清空当前基地 wishlist

按钮名：`清空基地 wishlist`

目的：
- 删除当前基地绑定 wishlist 中上一轮残留物资
- 保证后续生成的是本轮补货需求，不混入旧数据

前置条件：
- 已读取当前基地
- 已解析当前基地对应的 `wishlistId`

成功条件：
- 目标 wishlist 条目数量变为 0
- 日志记录清空前数量与清空后数量

失败条件：
- 找不到目标 wishlist
- 找不到清空按钮或接口
- 清空后仍存在残留条目

输出：
- `wishlistId`
- `clearedCount`

### 3. 检查飞船在交易所

按钮名：`检查飞船在交易所`

目的：
- 判断当前基地对应飞船是否可执行补货回运
- 防止飞船不在交易所时误买、误装、误发船

前置条件：
- 已读取当前基地
- 可读取公司飞船列表或页面飞船列表

成功条件：
- 找到当前基地对应飞船
- 飞船位置为交易所
- 飞船不是运输中

失败条件：
- 未找到对应飞船
- 飞船在基地
- 飞船运输中
- 飞船状态不可操作

输出：
- `ship`
- `shipLocation`
- `exchangeWarehouseId`

### 4. 创建适当天数补给 wishlist

按钮名：`创建补给 wishlist`

目的：
- 复用游戏 `Resupply` 页面计算缺料
- 按配置的补齐天数生成当前基地 wishlist
- 在 `TOTAL WEIGHT` 超过飞船容量时，以 `0.5` 天为单位下调补齐天数

前置条件：
- 已读取当前基地
- 已清空当前基地 wishlist
- 已读取补齐天数配置
- 最好已确认飞船在交易所，用于载重约束

成功条件：
- 如当前不在 `Base` 页面，先点击游戏内 `Base` 切回基地页面
- 如未选中当前基地，先从左侧基地列表选中当前基地
- 进入当前基地 `Resupply` 页面
- 设置目标补齐天数，真实游戏中只写入 `#days` 输入框，不写 `#resupplySlider`
- 勾选全部需要补给的物资
- 读取页面 `TOTAL WEIGHT`
- 当 `TOTAL WEIGHT` 大于飞船容量时，按 `0.5` 天为单位下调补齐天数
- 下调后必须再次真实写入 `#days`，并重新勾选全部需要补给的物资，不能只更新脚本日志或内部变量
- 下调后如果页面 `TOTAL WEIGHT` 仍大于飞船容量，继续按 `0.5` 天递减并重复读取重量
- 点击游戏的 `Add to Wishlist`
- 读取到生成后的 wishlist 条目
- wishlist 总重量不超过飞船容量

失败条件：
- 无法切回 `Base`
- 找不到真实游戏 `Resupply` 或 `Add to Wishlist` 控件
- 降到 `0.5` 天后 `TOTAL WEIGHT` 仍超过飞船容量
- 无法选中当前基地
- 无法进入 `Resupply`
- 无法设置天数
- 天数输入框仍保持旧值
- 无法勾选条目
- 无法添加到 wishlist
- 缩减到 `0.5` 天仍超重

输出：
- `wishlistRows`
- `finalDays`
- `estimatedWeight`
- `estimatedCost`

### 5. 购买 wishlist

按钮名：`购买 wishlist`

目的：
- 在交易所按 wishlist 逐项购买补给物资

前置条件：
- 已创建补给 wishlist
- 可用资金足够

成功条件：
- 内部自动读取当前基地绑定 wishlist
- 在当前基地 `Resupply` 页面点击 `View Wishlist` 进入交易所对应 wishlist
- 不设置 `location.href`，不刷新页面，必须通过游戏内可见控件切换页面
- 对每个 wishlist 条目执行：点击 wishlist 物资行、确认右侧购买数量、点击最终 `Buy`
- 最终 `Buy` 必须优先点击游戏真实 `#exBuyButton`，不能点击自动化面板内的 `购买 wishlist` 按钮
- 点击 Buy 前必须在游戏 `#exchangeTradeMatCard` 范围内核对右侧购买面板物资名与 wishlist 物资一致，并核对 `#inputQuantity` 等于 wishlist 数量
- 点击 Buy 后必须确认该物资 wishlist 行已从页面移除，才能写入“已购买”
- 购买成功后将本轮购买清单保存在脚本状态中，供 `转移到飞船` 使用
- 日志记录每个物资购买结果

失败条件：
- 找不到 `View Wishlist` 按钮
- `View Wishlist` 数量为 `0`
- 点击 `View Wishlist` 后未进入交易所 wishlist 页面
- 找不到物资行
- 找不到数量输入框
- 购买面板数量无法校准到 wishlist 数量
- 购买面板物资名与当前 wishlist 物资不一致
- 找不到最终 `Buy` 按钮
- 点击 Buy 后 wishlist 行仍存在，说明购买未确认成功
- 某项购买失败
- 用户点击停止

输出：
- `buySummary`
- `failedItems`

处理规则：
- 第一版遇到任一购买失败就停止后续购买，避免半自动状态下继续误操作
- 已买项目必须写入摘要

### 6. 转移到飞船

按钮名：`转移到飞船`

目的：
- 把本轮购买的补给物资从交易所仓库转移到当前飞船

前置条件：
- 飞船在交易所
- 本轮有购买结果或可读取交易所仓库库存
- 交易所页面可打开仓库 / 飞船转移界面

成功条件：
- 本轮 wishlist 中每种物资已转移到目标飞船
- 若 05 已经购买完成且游戏已清空 wishlist，优先使用 05 保存的本轮购买清单装船
- 点击转移前必须读取 `input[id^="btnradio-whwt"].checked` 对应标签或 active 标签，确认当前真实选中的是目标飞船
- 如果点击目标飞船标签后当前选中飞船仍不是目标飞船，必须立即失败，不能点击任何物资转移按钮
- 支持 `转移黑名单` 配置，配置位于 `一键购买 wishlist` 展开面板内，默认启用 `Ship Repair Kit (#113)` 与 `Antimatter (#149)`
- 执行策略保持玩家点击流程：按本轮购买清单逐项点击交易所仓库物资行右箭头，只转移未启用黑名单的物资
- 每点击一个物资行右箭头后，必须等待转移弹窗出现并点击确认勾，再处理下一个物资
- 不点击 `Exchange Warehouse` 总重量旁的一键转移箭头，避免黑名单物资先进入飞船
- 启用的黑名单条目不点击转移；禁用的黑名单条目按普通物资转移，允许用户临时把对应物资带回飞船
- 日志记录每项转移数量

失败条件：
- 找不到目标飞船
- 当前选中飞船不是目标飞船
- 找不到转移入口
- 找不到非黑名单物资的行转移按钮
- 找不到转移弹窗确认勾
- 找不到数量输入框
- 飞船载重不足
- 某项库存不足

输出：
- `transferSummary`

### 7. 飞船补油修理

按钮名：`飞船补油修理`

目的：
- 逐个切换飞船并判断当前位置
- 对当前位于交易所的飞船执行 `Refuel` 与 `Repair`
- 确保飞船燃料与耐久在返航前尽量补满

前置条件：
- 页面可读取飞船列表，或可从交易所仓库飞船标签读取候选飞船
- 交易所仓库或飞船上有足够 `Antimatter` 与 `Ship Repair Kit`
- 可打开飞船维护入口或选中对应交易所飞船标签

成功条件：
- 脚本会逐个点击候选飞船，切换到对应飞船详情
- 如果飞船详情面板顶部列出所有船名，必须点击精确匹配目标船名的标签，并以当前详情区域为准判断是否切换成功
- 交易所仓库飞船货仓页只显示飞船名、`Exchange Station` 和货物表时，不能视为维护详情，必须点击蓝色飞船名字进入包含 `Refuel` / `Repair` / `Start flight` 等控件的详情，不能把 `btnradio-whwt` 货仓标签当成维护详情入口
- 切换后读取当前飞船详情位置
- 当前不在 `Exchange Station` 的飞船会记录跳过，并继续下一艘，不停止整步
- 所有当前位于交易所的飞船都已依次执行 `Refuel` 与 `Repair`
- 每次执行维护时都先点击飞船信息面板中可见的 `Refuel` 或 `Repair` 按钮
- 点击后等待维护弹层打开，再填写数量并点击确认
- 等待维护弹层时忽略 tooltip 或其他没有可见数量输入框的 `.popover`
- `Repair` 阶段不能复用补油后残留的 `Refuel` 弹层，必须等到文本匹配修理语义的弹层
- 每次维护数量使用游戏弹层允许的最大值

失败条件：
- 缺少 `Antimatter`
- 缺少 `Ship Repair Kit`
- 找不到某艘飞船的信息入口或仓库标签
- 找不到补油或修理入口
- 点击补油或修理入口后维护弹层未打开
- 维护确认按钮不可用

输出：
- `maintenanceSummary`

### 8. 一键补修理包、油

按钮名：`一键补修理包、油`

目的：
- 补齐交易所仓库中的飞船维护消耗品
- 把 `Antimatter (#149)` 与 `Ship Repair Kit (#113)` 补到目标库存 `2000`

前置条件：
- 可读取交易所仓库库存
- 可进入交易所购买页面
- 交易所中存在对应物资可购买

成功条件：
- 库存低于目标时，按差额完成购买
- 库存已达到目标时，不执行购买并记录无需补货

失败条件：
- 找不到交易所页面入口
- 找不到对应物资购买行
- 找不到数量输入框或最终 `Buy` 按钮

输出：
- `restockSummary`

### 9. 发船回基地

按钮名：`发船回基地`

目的：
- 将飞船从交易所发回当前基地

前置条件：
- 飞船在交易所
- 已完成购买与装船
- 已补油
- 已修理或确认无需修理

成功条件：
- 选择目标为当前基地
- 动力模式选择普通
- 根据需要开启自动卸货
- 点击出发
- 飞船状态变为运输中

失败条件：
- 找不到目的地输入
- 找不到当前基地目的地
- 找不到动力模式
- 找不到自动卸货开关
- 找不到出发按钮
- 点击后状态未变化

输出：
- `flightSummary`
- `waitMs`

## 编排功能

### 一键购买 wishlist

第一阶段定义：
- 只执行 `读取当前基地`、`读取 wishlist`、`打开交易所`、`购买 wishlist`
- 不清空 wishlist
- 不创建 wishlist
- 不装船
- 不发船

用途：
- 单独验证“已有 wishlist 的购买能力”
- 降低真实交易风险

### 一键补货回运

第二阶段定义：
- 按 9 个原子步骤执行完整流程
- `打开交易所` 与 `读取 wishlist` 不再单独展示为补货回运原子步骤，改为 `购买 wishlist` 内部动作
- 任何关键步骤失败立即停止
- 进入运输中后以 `waiting` 结束

用途：
- 替代旧 `补货` 链路，成为稳定的补货主流程

## 配置项

当前阶段需要新增或确认以下配置：

- `补齐天数`：已有配置，创建 wishlist 时使用
- `最低补齐天数`：缩减天数的下限，默认 1
- `自动卸货`：发船回基地时默认开启
- `补油目标`：默认尽量补满
- `修理目标`：默认尽量修满
- `购买前预览`：默认关闭；后续可选开启确认模式
- `失败后继续`：第一版默认关闭
- `转移黑名单`：06 `转移到飞船` 使用，默认启用 `Ship Repair Kit (#113)` 与 `Antimatter (#149)`，用于逐项装船前过滤这些物资，不点击其转移按钮

配置保存规则：
- 每一项新增配置都必须同步保存、读取、渲染
- 不得因为保存其它配置而丢失已有物资图标、白名单、黑名单字段

## 状态与日志

每个原子功能都要写入统一步骤日志：
- 开始时间
- 前置条件检查结果
- 关键点击动作
- 成功摘要
- 失败原因
- 已停止状态

日志文字必须能让用户判断当前卡在哪一步，不能只写“失败”。

## 风险控制

真实购买与发船有经济和时间成本，必须按下列规则控制：

- 没有明确 wishlist 时不购买
- 资金不足时不购买
- 飞船不在交易所时不装船、不补油、不修理、不发船
- 目标基地不明确时不发船
- 任一关键 UI 控件找不到时停止
- 默认不使用热注入作为正式发布方式
- 每次脚本更新后执行 `npm run release:local`

## 验收标准

第一阶段验收：
- `一键购买 wishlist` 展开面板内能看到所有拆分按钮
- 每个按钮点击后都有日志，即使尚未接入真实流程也能显示明确状态

第一版购买验收：
- 已有 wishlist 时可以单独执行购买
- 空 wishlist 不购买
- 资金不足不购买
- 任一购买失败时停止后续购买

完整补货回运验收：
- 当前基地明确
- 当前基地 wishlist 能清空并重建
- 飞船必须在交易所
- wishlist 能按适当天数生成
- 购买物资能转移到飞船
- 飞船能补油、修理
- 飞船能以普通动力发回当前基地并开启自动卸货
- 面板日志能还原完整执行过程
